# 73. Engines run in a per-attempt sandbox, and isolation is claimed only for what runs there

Status: accepted, 2026-11-15. Spec #90, story 106. Builds on ADR 0021, 0035 (ACP engines have no native tools) and 0037 (egress proxy).

ADR 0035 had the runner state `ephemeral-container` for Pi, Claude and the fixture, but Pi and Claude ran in the runner process; only broker tools ran in launcher containers. A statement of isolation must be what runs.

## Decision
1. **One sandbox per attempt and route.** The runner asks the launcher (`POST /v1/engine-sandboxes`) to run an engine's host process (`engines/sandbox-host.ts`) in its own container. The launcher alone shapes it: fixed image `brain-sandbox-engine`, `--read-only`, `--cap-drop ALL`, `no-new-privileges`, `--cpus`/`--memory` from the job's reservation (`placement.resources`), `--pids-limit 512` (the reservation has no pid field; the bound is the launcher's, above a tool's 128), a `/tmp` tmpfs, `--rm`. The caller names only the engine (from a list), attempt, request id, the two numbers and hosts; any other field is a 422 before docker runs.
2. **One mount.** `<BRAIN_LAUNCHER_ENGINE_STATE_ROOT>/<attemptId>` at `/state`, writable. The caller gives no path: the id is validated and the directory must exist under the operator's root and not be a link. The engine runs as `BRAIN_LAUNCHER_ENGINE_USER` (default the launcher's uid:gid). Pi keeps saved conversations in `/state/.pi-agent`; the runner places a held checkpoint in the new attempt's directory before a resume and keeps a directory past its attempt only if it holds one (newest 20).
3. **Network only through the proxy.** `brain-internal` plus a grant (ADR 0037) of the workspace's `egressHosts` and the attempt's model host(s): the route's, else the runner's own address for the engine (`BRAIN_LOCAL_MODEL_URL` or Pi's default, the Anthropic base URL or `api.anthropic.com`, or `BRAIN_ENGINE_MODEL_HOSTS` for an ACP agent, which picks its own model). `NODE_USE_ENV_PROXY=1` makes the engine's clients use it. No hosts: `--network none`.
4. **Secrets by reference.** No key travels in argv, the container environment or the launcher request. The runner resolves the credentials the engine reads (the route's `BRAIN_MODEL_KEY_<reference>`, the local model key, the Anthropic key) from its own environment and sends them in the host's first frame over stdin, with the few non-secret settings. Nothing else of the runner's environment goes.
5. **The engine stays behind the port.** `SandboxedEngine` implements `EngineAdapter` by forwarding each call as JSON lines to the host, which builds the unchanged engine with `selectEngine`. Tool proposals leave through the event stream and the runner's broker answers as before: the engine gains no authority. Probing at an attempt happens in the sandbox, so the model must be reachable from there. The launcher holds the container's stdin/stdout and hands lines over by input and long-poll output calls on its authenticated socket.
6. **No downgrade.** An engine this runner can sandbox never runs in the runner. If the sandbox cannot start (no launcher, state root missing, Docker down, image absent, request refused) the attempt fails with `engine sandbox create failed …` and the launcher's reason, which the Governor classes as `sandbox-image-missing` or `sandbox-unavailable`; a sandbox that ends mid-session fails with `engine sandbox exec failed: …`. There is no fallback, flag or retry.
7. **A sandbox does not outlive its runner.** The launcher stops a sandbox its runner has not spoken to for `BRAIN_LAUNCHER_ENGINE_IDLE_MS` (90 s; the runner polls every 20 s) and drops its grant; at start it removes leftover engine containers and prunes their grants. The host also stops when its stdin closes.
8. **The statement follows what runs.** `engineIsolation(engine, sandboxAvailable)` serves both the hello/heartbeat statement and the runner's choice of engine for a step. Pi, Claude, ACP, OpenCode and Codex state `ephemeral-container` only while the runner is set up for sandboxes (a launcher and `BRAIN_RUNNER_ENGINE_STATE_DIR`) and the launcher answers with Docker up and the engine image built; else `trusted-local`, and a step requiring `ephemeral-container` is not placed on it. ACP engines may now claim it because the container, not the agent's word, contains them (0035's checks stay as defence in depth). The fixture keeps `ephemeral-container` either way: it runs no model, agent code or tool, so a sandbox would contain nothing, and it never runs in one. An unlisted engine is `trusted-local`.

## Limits (be honest)
- The runner's own probe at hello and heartbeat (does the model answer) still runs in the runner: a models-list request, no agent code. An engine whose model the runner cannot reach directly is not advertised.
- ADR 0037's limits apply. Only what the engine wrote to `/state` survives a dead sandbox.
- Limits are the step's own reservation: a step that runs an agent must reserve for the engine process. Below the launcher's bounds (100 millicores, 128 MB) a request is refused; an offer with none gets 1 cpu and 1 GB.
- Launcher health ignores a missing engine image unless the runner has `BRAIN_RUNNER_ENGINE_STATE_DIR`: without engine sandboxes it keeps running tools and the fixture.
- The image (`deploy/engine-sandbox.Dockerfile`) has Pi and Claude; an ACP agent's binary is the operator's to add. Proven against a recording stand-in for `docker` and an in-process host: no real container, OpenCode or model was started, and the image was not built here.
