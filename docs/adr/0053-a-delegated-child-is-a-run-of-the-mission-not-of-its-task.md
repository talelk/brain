# 53. A delegated child is a run of the mission, not of its parent's task

Status: accepted, 2026-11-15. Spec #90, stories 36 to 38. Builds on ADR 0003 (members are peers), 0032 (session principals) and 0042 (Brain tools). Supersedes the depth and child numbers of ADR 0003.

A delegation recorded a child session that nothing ran, and its human review had no screen.

## Decision
1. **The child has a run of its own.** `session.delegate` commits the child session, the delegation and a `delegation_runs` row (pending). A pump (`DelegationRuns`) starts the run through the workflow engine after the command commits and on every maintenance pass, with the delegation as execution key, so a crash between the two is repaired and a run never starts twice. The job is created, admitted against the mission's member cap and budget, placed and claimed like any task's. The child counts as one more running member and spends the mission's budget; the parent never waits for it (at a cap of one that would deadlock).
2. **It is not a run of the task.** The run is not in `execution_links`, so it never moves the task to review, counts no failed attempt, is not the task's result, and is never retried by the task's rules. Readers that need the mission (admission, session binding, context pack, run read, knowledge scope, stop-all, the stream) also read `delegation_runs`. The child acts as a team member's principal (the named member, else the delegating task's) and has no task of its own, so its Brain tools do not default to the parent's task.
3. **The result is a handoff of its own.** A finished child writes a handoff on the parent's task with `delegation_id` set. It never supersedes the member's own handoff and is read by no dependent, Done check, bundle, judge or reuse; it is accepted after the task is done. The parent reads it in `sessions.context` and its context pack as the child's claim, and is steered with it when live and steerable. A failed child is a failure fact on the delegation, told the same way, and asks no person.
4. **A session delegates only from itself**, with a limit set by the agent definition: `maxChildren` per session (at most 4), `maxDepth` for the tree (now up to 3, the platform depth); a session whose agent allows no children cannot delegate. A child's budget defaults to half of what its parent has unreserved. Depth over 3 is refused with a plain sentence.
5. **`mission.delegate` is a Brain tool** (story 36 is the session's own action) behind `session.delegate`, allowlisted deliberately. The Governor, not the model, names the parent and checks the mission. The starter ships the tool but gives it to no agent and keeps `maxChildren` 0: turning delegation on is a release decision that cannot be qualified without a real model.
6. **Review.** `delegation.review` stays human-only and independent: the person who started the delegation, or any team member, never reviews it. Accepting needs a verified bundle and an independent verdict; a person may always reject. The screen is the mission's Delegated work tab (linked from the task); it offers the child's own evidence digest, never a field to paste one, and says why a viewer cannot decide.

## Limits
- A session's budget slice bounds what a parent hands out; the attempt itself is stopped by its agent's caps and the mission's budget.
- The child runs the workspace's way of working or the general task workflow; it cannot name another.
