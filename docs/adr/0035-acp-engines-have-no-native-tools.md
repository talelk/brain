# 35. ACP engines have no native tools

Status: accepted, 2026-11-14. Closes the hole ADR 0021 leaves open for ACP agents.

ADR 0021 says an agent reaches the host only through operator-declared tools. The ACP engine (OpenCode, any `acp` agent) did not keep that: the client answered no permission requests, and OpenCode's default is to allow its own shell, edit and fetch without asking, so an OpenCode session could act on the runner host while the runner reported `ephemeral-container` isolation.

## Decision
1. **No client capabilities.** The adapter declares none (`fs` and `terminal` false). Any request from the agent other than a permission request is answered `-32601`. Requests are told from responses by `method`, never by `id`: the agent's request ids are its own.
2. **Permission requests are refused unless they name a broker tool.** Allowed: `toolCall.name` is exactly the name of a tool in the session's `allowedTools` (matched by id and digest), the agent does not call it a command, edit or fetch, and the agent offers `allow_once`. Then `allow_once` is chosen, never `allow_always`. Anything else gets the agent's `reject_once`, or `cancelled` if it offers none. Title and input decide nothing.
3. **OpenCode starts with its native tools denied** (`OPENCODE_CONFIG_CONTENT`: ask everything, then deny shell, edit, write, patch, read, glob, grep, webfetch, websearch, external_directory, subagent, lsp), with project config and Claude Code compatibility off, so a repository's `opencode.json` cannot allow them again. Without these rules OpenCode never asks, and (2) is never reached.
4. **A native tool that runs ends the session.** A tool call that reaches `in_progress` or `completed` and is not an allowed broker tool stops the agent and fails the session (`POLICY_DENIED`). A call that was only attempted and refused is not a violation.
5. **Isolation is stated per engine.** The runner states `engine-isolation:<engine>:<mode>` for each engine it probed (hello and every heartbeat; an operator cannot configure it). Fixture, Pi and Claude run in the runner process with no native tools: `ephemeral-container`. ACP engines, and any engine not listed, are `trusted-local`: the agent is a separate process of the runner's user that nothing outside it contains. Placement uses an engine only if it states the step's isolation; no statement means no. The runner picks the same way, so a runner with both kinds of engine never runs a step on the one that cannot meet it. Placement still compares isolation by equality; ordering and the policy floor belong to the policy ticket.

6. **An ACP engine runs a whole attempt (spec #90, ticket 142).** `start` opens the session, sends one `session/prompt` with the job's instructions then `Task:` and the task (the task already carries the context pack), and streams the agent's updates as engine events. The stream ends with exactly one terminal event: `completed` with the output artifact (the text after the agent's last tool call; earlier narration is a diagnostic note) and, when the agent reports it, a final-total `usage` event; `error` plus `session.stopped` for a refusal (`POLICY_DENIED`), the agent's own limit or more tokens than the job allows (`BUDGET_EXHAUSTED`, stopped as `budget`), an unknown stop reason or an agent that dies (`DEPENDENCY_UNAVAILABLE`); `timeout` when the prompt outlasts `limits.timeoutMs` (the agent is sent `session/cancel`); `cancelled` when the runner cancels or aborts. `cancel` asks the agent to stop, waits at most 500 ms for it to say so, then ends the process. An agent that reports no usage is charged the runner's flagged estimate.
7. **Broker tools reach the agent through a runner MCP bridge.** When the job declares tools, `session/new` carries one MCP server, `brain`: a loopback HTTP endpoint of the runner (port chosen per attempt, bearer token made per attempt, compared in constant time, closed when the attempt ends). The agent is given it as `http` when it advertises `mcpCapabilities.http`, else as a `stdio` command (`mcp-relay.mjs`) that only pipes lines to the endpoint. The endpoint serves `tools/list` and `tools/call` for the job's declared tools only; any other name is a JSON-RPC error before anything is proposed. A call goes through `GovernedToolCalls`, the path Pi and Claude use: it becomes a `tool.proposed` event, the supervisor's `executeTool` checks the pinned release, target and input, proposes a change as a held job (ADR 0028) or runs a read through the launcher with its permit (ADR 0021, 0024), and the receipt comes back as the MCP result. The job's `maxTurns` bounds the calls. The bridge is the boundary; the permission rule in (2) is a second check.
8. **Codex is an ACP engine** (`codex`; command `BRAIN_CODEX_COMMAND`, default `codex acp`; `trusted-local`).

## Limits (be honest)
- (3) is unverified against a running OpenCode: nobody has run it with these settings. (2) and (4) go by what the agent says about itself; a lying agent is not stopped. This is why ACP engines are `trusted-local` and a step that requires `ephemeral-container` is never placed on one, until the per-attempt sandbox for engines (spec #90, story 106) exists.
- The Codex profile passes the agent no settings: this repository documents neither Codex's ACP command nor its configuration format, so none is guessed. Its native tools are held back only by (1), (2) and (4). Qualification of the real Codex has NOT been run and needs the owner's explicit permission; nothing here says how Codex behaves.
- The shapes in (6) and (7) follow the ACP and MCP specifications as recalled, never a run against a real agent: the `stdio` and `http` `McpServer` entries, the prompt result's `usage` (`inputTokens`, `outputTokens`, `cachedReadTokens`) and `stopReason` values. They are tested only with the fake agent. An agent that names a bridge tool differently from `brain_<tool id>` in its permission requests and tool-call updates would be refused and stopped by (2) and (4) until the adapter learns that name; fail-closed, not a bypass. ACP engines remain unable to state `ephemeral-container` (#151 is open), so starter workflows that require it are never placed on them.
- The operator's own OpenCode configuration (providers, plugins, MCP servers) is still loaded: it supplies the model.
