# 65. Secrets are leased per attempt through an adapter port and end with the attempt

Status: accepted, 2026-11-15. Builds on ADR 0021 (agents reach the host only through operator-declared tools), ADR 0024 (effect permits), ADR 0032 (a session credential is bound to its attempt), ADR 0037 (egress) and ADR 0047 (stop all sessions). Weakens none of them.

Secrets were three unrelated things: runner-local 0600 files for privileged tool slots, git credentials encrypted in the Governor, and model keys in the runner's environment. A runner kept long-lived secrets on disk, nothing expired, and nothing ended a use when the attempt did.

## Decision
1. **A port, with the broker in front of it.** `SecretsAdapter` (`apps/governor/src/modules/secret-leases/port.ts`) only turns a reference into material for one workspace: `serves(ref)` and `resolve(scope, ref, notAfterMs)`. It may return its own expiry. The Governor's `SecretBroker` owns everything else (binding, lifetime, revocation, audit), so a replacement adapter cannot weaken it. Built in: `EncryptedStoreAdapter` (references `git:<connectionId>`, served only to a workspace with a verified write binding to it) and `HostFileAdapter` (`$BRAIN_TOOL_SECRETS_DIR/<workspace>/<name>`, mode 0600, on the Governor host). No vendor SDK; a vault is another adapter.
2. **A secret credential is a lease**, a `secret_credentials` row: attempt, the job fence it was minted under, reference, adapter, expiry, revocation. It never holds the value, and no event or audit entry names one (they name the reference, the attempt and the credential id). Lifetime is `min(attempt deadline + 30 s, now + 1 h, the adapter's own expiry)`.
3. **It holds only while its attempt does.** Checked on every use against the same predicate a session credential uses (`attemptHoldsFence`: running under the fence, lease current, runner epoch, runner not quarantined or disabled). Revoked in the record when the attempt ends, loses its lease or hits its deadline, on stop-all (attempts and the whole workspace), and on runner quarantine, rotation or deregistration. Use after any of that, or after expiry, is refused and audited as `secret.refused`.
4. **Declared means the pinned payload.** For a runner the Governor mints only the `secretRefs` of the attempt's own privileged tool step, read from the job payload; the runner names nothing. An agent step, an evaluator, a merge and a held change (`act`, whose input came from a model's proposal) declare none and get none. The runner delivers them over its authenticated channel (`POST /runner/v1/attempts/{id}/secret-credentials`), holds them in memory for the one call, re-checks them with the Governor immediately before use (`.../validate`, which also audits a refusal), and hands them to the privileged-tool sandbox as that one exec's environment through a launcher field accepted for that profile only. Values are scrubbed from stdout, stderr and error text as before.
5. **git.open-pr stays in the Governor.** The runner never sees the git token. The held change's attempt mints a lease for `git:<connection>` through the port, the push and the provider call use it, and it is revoked when the call ends.

## Consequences
- The runner-local secret store (`BRAIN_SECRETS_DIR` on a runner) is gone; those files move to the Governor host. No migration.
- Be plain about the limit: a stored static token cannot be made provider-short-lived by the Governor. What is short-lived is the lease, the runner's possession of the value and its use. An adapter that issues a real short-lived upstream credential gets that for free through `expiresAtMs`.
- Model keys (`BRAIN_MODEL_KEY_<REF>`, ADR 0055) stay as runner environment variables: the engine reads them directly and a lease would only add a hop.
- External MCP header secrets (#137) are not on this base; when they land they take a `secretRefs`-style declaration and this port.
- Pull-request status reads and the integration verification still read the stored connection directly: they are not attempt work.
