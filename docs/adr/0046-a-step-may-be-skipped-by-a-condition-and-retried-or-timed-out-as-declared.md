# 46. A step may be skipped by a condition, and its declared retry and timeout are enforced

Status: accepted, 2026-11-15. Spec #90, stories 69 and 70. Builds on ADR 0019, 0020, 0033 and 0043.

A step declared `retry` and `timeoutSeconds`, and nothing read them; a workflow could not branch on what an earlier step produced.

## Decision
1. **`when`.** Any step may declare `when: { step, pointer, equals? }`: true when `pointer` resolves in the output of `step`, and, if `equals` is given, resolves to a value equal to it (compared structurally, key order ignored). The scheduler (`readiness` in `admitReadySteps`, ADR 0043) reads it once every need has succeeded; a false condition sets the step `skipped`, not `failed`.
2. **A skip runs down its chain.** A step with a skipped need is skipped. There is no override: a join that needs a branch which may be skipped is skipped with it, so a gate that dominates a step before the skip still dominates after it. A workflow that wants a join to run anyway has the join need the step before the branch.
3. **A run with skipped steps succeeds.** A step is skipped in a run that has not failed only because a condition was false or a need was skipped, so the run ends `succeeded` and the mission is told, as when every step ran. Failure and cancellation end the run before any step is skipped by them. (`partial` stays in the run machine; nothing produces it from a skip.)
4. **Checked at compile time**, in `compileWorkflowGraph`, so a bad release is refused at stage: the pointer is a JSON pointer, `step` exists and is a transitive need of the step (its output is final when the condition is read), and an evaluation step has no `when` (it is admitted from evidence, not from its needs' outputs). `retry` and `timeoutSeconds` are refused on gate, steer and subgraph steps, which run no job; `retry` must be a valid policy, its delays ordered, and `transient-read` is refused on a step that changes a target.
5. **Retry** is a count of attempts of the one job (`maxAttempts` includes the first). A failed attempt is offered again when the step's `retry` allows: the job goes back to `queued` (so the claim applies the member cap and budget, ADR 0009, 0016, 0043) with `ready_at_ms` after the backoff (`initialDelayMs` doubling to `maxDelayMs`), and the run is not told of a failure. The job keeps its execution key, so a step still never starts twice; `jobs.step_failures` counts the attempts that failed on their own account, not platform interruptions. Not retried, and the step fails as before: a quota failure (ADR 0033: the task waits it out and no retry is spent), a job any of whose attempts took an effect permit or a resource lease or proposed a change (the target may have changed: a fresh attempt after a held change was carried out, or after a reconciled-absent one, is not retried either), a failure whose class the retry does not name (`transient-read` for a read step; `target-proven-absent` for a step that changes a target and whose attempt took neither permit nor lease), and a step that used its attempts.
6. **Timeout** bounds one attempt. When an attempt starts running, `job_attempts.deadline_ms` is set from the step's `timeoutSeconds`; the maintenance pass (and each claim) ends a running attempt past it. An attempt that took no permit or lease fails (reason "The step timed out after N seconds.", failure code `timeout`) and goes through the same retry decision; one that may have changed a target becomes `outcome_unknown` for reconciliation and is never retried. The runner finds its attempt fenced at its next lease renewal and stops. `jobs.deadline_ms` is unchanged: it bounds how long a job may wait to be claimed.

## Rejected
- **A `when` that skips only its own step and lets dependents run.** The dependent would read an output that does not exist.
- **Counting `attempt_counter` against `maxAttempts`.** It also counts declined and expired offers and platform restarts, which are not the step's failures.
- **Stopping a timed-out attempt by shortening its lease.** A lease that runs out is a platform interruption, which restarts without counting: a free retry loop.

## Limits
- The token allowance of a task (failure class budget) is judged when a run fails, not before a retry; a retried attempt is still claimed under the mission's budget and member cap.
- A step skipped by a condition leaves no output: a workflow output or a binding that reads it is unavailable.
- Evaluation steps with a `timeoutSeconds` now stop at it; the runner had only timed agent steps. The starter's evaluators declared 30 s, which nothing enforced, and now declare 300 s.
