# 45. Stop all sessions reuses the fence, and an administrative command takes its own step-up

Status: accepted, 2026-11-15. Spec #90, stories 112 and 113.

An administrator had no emergency stop and no screen for the autonomy ceiling. The mechanisms an emergency stop needs already exist in pieces: a job fence that makes a runner's calls answer LEASE_LOST, permits and session credentials that die with their attempt, a mission pause. The decisions are how to combine them without a second path, and what "needs step-up" means for a command that is not an approval.

## Decision
1. **Stop all is one command**, `workspace.sessions.stopAll` (`workspace:admin`, a reason, one control transaction). It does not suspend the workspace: people keep reading, deciding and resuming, and `workspace.control` suspend keeps its own meaning (nothing new is dispatched or approved).
2. **Fence.** Each live attempt of the workspace (offered, running, uploading) has its job's `job_fence` moved on, the same move a lost lease makes, so renew, events, completion, permit and credential calls all answer LEASE_LOST. The attempt ends `cancelled` (an unclaimed offer `declined`) and its job `cancelled`; jobs nobody holds (queued, blocked) are cancelled too, or they would start the moment a mission resumed.
3. **An effect that started is never called cancelled.** An attempt holding a permit beyond `issued` ends `outcome_unknown` with its job, the same state a lost lease leaves, so Needs you asks a person to check before anything goes on. Permits only `issued` become `revoked` and release their resource lease; every permit credential of the attempt is revoked. The organization revocation generation is not bumped: it is organization-wide and would invalidate other workspaces' permits.
4. **Credentials.** The attempt's session credentials (ADR 0032) are revoked, and so is every credential of the workspace's machine principals, whatever attempt it was minted for. Capacity reservations are released and the session ends `stopped`.
5. **Missions are left paused, with a reason, never abandoned.** Every active mission pauses; the administrator's reason is stored on the mission (`stop_note`, a new column with a default, so the pause reason enum stays `human`) and read as pause reason `stopped`. Tasks whose runs were cancelled return to `ready` with a next action naming the stop; they are not failures and do not count toward parking. The stopped mission shows as a needs-attention item with the reason, and a coordinator is not admitted into it (a budget pause still lets one write its checkpoint). `mission.resume` clears it and auto-start runs the ready tasks again, as new attempts.
6. **Audit.** One `workspace.sessionsStopped` event names the person, the reason and the counts; the audit trail shows its message. Setting the ceiling emits `workspace.autonomyCeilingSet` in place of the generic `workspace.updated`.
7. **Ceiling.** `workspace.autonomyCeiling.set` takes a preset (`supervised`, `standard`, `autonomous`), not an operation list; `engineSettings.get` reads it back with what stop-all would stop (running sessions by mission, standalone, waiting) so the confirmation can name it. The ceiling applies when a mission is created or its autonomy is changed; missions already running keep their policy.
8. **Step-up for an administrative command.** The approval step-up (ADR 0024) is bound to one approval and its table requires one, so these commands get their own: `command_step_ups` binds a challenge to the person's session, the command type, the workspace and the digest of the exact payload; verifying it (a current TOTP code when two-factor is required) makes it evidence; the command spends it once inside its own transaction (`STEP_UP_COMMANDS` lists the commands that take it). A different reason, preset, command, workspace or session, an unverified or spent challenge, or a machine credential is refused. Restore revokes outstanding step-ups with the other evidence.

## Limits (be honest)
- The runner learns it was fenced at its next call; the engine process may run until then. Nothing it reports or does through Brain is accepted, but a tool it already launched outside Brain is not reached.
- A job whose attempt already finished and waits for its verdict (`verifying`) cannot move to `cancelled`, so it stays as it is, as after `workflow.cancel`; its run is cancelled and its queued evaluator jobs are cancelled.
- A mission plan being drafted is stopped too and is not drafted again by reading it; the person asks again after resuming.
- A stopped delegation or child session is ended with its attempt; the parent task returns to ready, not to the delegation's own result.
- The stop is per workspace; there is no organization-wide stop.
