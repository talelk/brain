# 65. Engines run in a per-attempt sandbox, and isolation is claimed only for what runs there

Status: accepted, 2026-11-15. Spec #90, story 106. Builds on ADR 0021 (agents reach the host only through declared tools), 0035 (ACP engines have no native tools) and 0037 (the egress proxy).

ADR 0035 had the runner state `engine-isolation:<engine>:ephemeral-container` for Pi, Claude and the fixture. That was not true of Pi and Claude: their engines run in the runner process; only broker tools run in launcher containers. A statement of isolation must be what runs.

## Decision
1. **One sandbox per attempt and route.** The runner asks the launcher to run an engine's host process (`apps/runner/src/engines/sandbox-host.ts`) in its own container (`POST /v1/engine-sandboxes`). The launcher alone shapes it: image `brain-sandbox-engine` (fixed), `--read-only`, `--cap-drop ALL`, `no-new-privileges`, `--cpus` and `--memory` (and equal swap) from the job's resource reservation (`placement.resources`), `--pids-limit 512` (the reservation has no pid field; an engine needs threads and, for an ACP agent, child processes, so the bound is the launcher's own, larger than a tool's 128), a 256 MB `/tmp` tmpfs, `--rm`, and a fixed `-i` stdio. The caller names only the engine (from a list), the attempt, a request id, the two numbers and the hosts; any other field is a 422 before docker is called. A repeated request id is the same sandbox.
2. **One mount.** `<BRAIN_LAUNCHER_ENGINE_STATE_ROOT>/<attemptId>` at `/state`, writable, and nothing else of the host. The caller never gives a path: the attempt id is validated, the directory must already exist under the operator's root and not be a link. The engine runs as the launcher's `BRAIN_LAUNCHER_ENGINE_USER` (default the launcher's own uid:gid), which must own that root as the runner does. Pi keeps its saved conversations in `/state/.pi-agent`; the runner places a held checkpoint into the new attempt's directory before a resume, and keeps an attempt's directory only when it holds one (the newest 20).
3. **Network only through the proxy.** The sandbox gets `brain-internal` and a grant (ADR 0037) of the workspace's `egressHosts` plus the model host(s) of the attempt: the route's host for a routed attempt, else the runner's own address for the engine (`BRAIN_LOCAL_MODEL_URL` or Pi's default, the Anthropic base URL or `api.anthropic.com`, or the operator's `BRAIN_ENGINE_MODEL_HOSTS` for an ACP agent, which picks its own model). `NODE_USE_ENV_PROXY=1` makes the engine's HTTP clients use the proxy. No hosts: `--network none`.
4. **Secrets by reference.** Neither the key nor any value travels in argv, the container's environment or the launcher request. The runner resolves the credentials the engine reads (the route's `BRAIN_MODEL_KEY_<reference>`, the local model key, the Anthropic key) from its own environment and sends them in the host's first frame (`init`) over the container's stdin, with the few non-secret settings the engine reads. Nothing else of the runner's environment goes.
5. **The engine stays behind the port.** `SandboxedEngine` implements `EngineAdapter` by forwarding each call over JSON lines (`probe`, `start`, `events`, `toolResult`, `cancel`, `checkpoint`, `steer`, `pause`, `continue`, `dispose`) to the host, which builds the unchanged engine with `selectEngine` and serves it. Tool proposals leave through the event stream and the runner's broker answers them as before: the engine in the sandbox has no authority the in-process engine did not have, and a tool still runs in its own launcher container. Probing at an attempt happens in the sandbox, so the model must be reachable from there. The launcher holds the container's stdin and stdout and hands lines to the runner by input and long-poll output calls on the existing authenticated socket.
6. **No downgrade.** An engine this runner can sandbox is never run in the runner. If the sandbox cannot start (no launcher, state root missing, Docker down, image absent, a refused request) the attempt fails with `engine sandbox create failed …` plus the launcher's reason, which the Governor already classes as `sandbox-image-missing` or `sandbox-unavailable`; a sandbox that ends mid-session fails with `engine sandbox exec failed: …`. There is no fallback path, flag or retry in the runner. A sandbox that failed to start stays failed for that attempt's engine.
7. **A sandbox does not outlive its runner.** The launcher stops a sandbox its runner has not spoken to for `BRAIN_LAUNCHER_ENGINE_IDLE_MS` (90 s; the runner polls every 20 s) and drops its grant; at start it removes every engine container left from before (its stdin was the old process) and prunes their grants. The host process also stops when its stdin closes.
8. **The statement follows what runs.** `engineIsolation(engine, sandboxAvailable)` is the one function for both the hello/heartbeat statement and the runner's choice of engine for a step. Pi, Claude, ACP and OpenCode state `ephemeral-container` only while the runner is set up for sandboxes (a launcher and `BRAIN_RUNNER_ENGINE_STATE_DIR`) and the launcher answers with Docker up and the engine image built; otherwise `trusted-local`, and a step that requires `ephemeral-container` is not placed on it. ACP engines may now state `ephemeral-container` because the container, not the agent's own word, is what contains them (ADR 0035's checks stay as defence in depth). The fixture engine keeps `ephemeral-container` in both cases: it runs no model, no agent code and no tool (it answers from its script and proposes broker tools), so a sandbox would contain nothing, and it never runs in a sandbox. An engine not named in the runner's table is `trusted-local`.

## Limits (be honest)
- The runner's own probe at hello and heartbeat (does the engine's model answer) still runs in the runner process, a models-list request and no agent code; an engine whose model the runner cannot reach directly is not advertised.
- Matching and DNS limits of ADR 0037 apply to the sandbox's network. A model host on a private address is reachable by listing it, as before.
- A sandbox may die with its attempt's saved conversation unsynced: only what the engine wrote to `/state` before the container ended survives.
- The image is built by `deploy/engine-sandbox.Dockerfile` (`scripts/build-sandbox-images.sh`) and has Pi and Claude; an ACP agent's binary is the operator's to add. Proven against a recording stand-in for `docker` and an in-process host; no real container, OpenCode or model was started, and the engine image was not built here.
- `--user` is one value for the engine; a deployment where the runner and the launcher run as different users must make the state root writable by both (group) or set `BRAIN_LAUNCHER_ENGINE_USER` to the runner's uid:gid.
