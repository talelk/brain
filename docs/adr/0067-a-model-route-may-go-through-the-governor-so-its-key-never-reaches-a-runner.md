# 67. A model route may go through the Governor, so its key never reaches a runner

Status: accepted, 2026-11-15. Amends ADR 0055 point 7 (a key is resolved by whoever calls) for routes an owner marks `viaGateway`; ADR 0023 (hosted model for checks and second attempts) is unchanged.

Every model key lived in the environment of the runner that called the vendor. A runner that is compromised, or simply shared, then holds a vendor key, and the Governor had no say in what an attempt sent or spent once it had the key.

## Decision
1. **Optional and off by default.** A model route has a switch, `viaGateway` (set in Administration > How work runs, with the rest of `workspace.modelRoutes.set`). Off, the route is exactly as ADR 0055 says: the runner holds `BRAIN_MODEL_KEY_<REFERENCE>` and calls the vendor. On, the key reference is read on the **Governor host** only, and the runner never sees the key, the reference or the vendor's address.
2. **One endpoint, OpenAI-compatible.** `POST /model-gateway/v1/routes/{routeId}/chat/completions` forwards to the route's upstream `<address>/chat/completions` with the Governor-held key and the route's model (whatever model the caller named is replaced). A stream stays a stream, chunk by chunk. Pi's `openai-completions` path is the single code path: a gateway route is an ordinary hosted route whose address is the Governor's and whose credential is the attempt's gateway token. The Claude engine speaks the Anthropic protocol and is not offered a gateway route (it is skipped like an engine that cannot serve it).
3. **The credential is a per-attempt gateway token**, with the binding rules of the attempt's other credentials (session credential, ADR 0042; short-lived secret leases, ADR 0065 where it is merged): minted for one running attempt and the fence it holds, asked for by the runner after its attempt starts (`POST /runner/v1/attempts/{id}/model-gateway-token`, never carried in the pinned execution artifact, an offer or an event), shown once and stored only as a digest, replaced when asked again, expiring at the attempt's deadline plus 30 s (and never beyond one hour). On every call the Governor re-checks that the attempt runs under the same fence, its lease is live, the runner's epoch is current and the runner is neither quarantined nor disabled, and the workspace is active. It is revoked when the attempt ends, is released, expires its lease or is stopped, and by stop-all. (#154's secret broker was not on this base, so the token is implemented here with the same rules; the two can be unified when both are merged.)
4. **Routes, prices and cooling are enforced centrally.** A call is accepted only for a route the job was offered (the list pinned in its payload, ADR 0055) that is still `viaGateway`, switched on and complete. A route that is cooling is refused at once with 429 and `Retry-After`, never sent upstream. A vendor 429 starts the cooldown centrally with the vendor's wait and is passed through unchanged (status, `Retry-After`, body), so the runner's own failover (ADR 0055 point 4) moves to the next route, gateway or direct, by the same path as for a direct route. The Governor does not fail over inside a call.
5. **Money stops the call.** Before forwarding, the Governor refuses when the run's mission has spent its money (settled plus reserved, or what this attempt already spent through the gateway, above the mission budget) or the workspace cap is reached. The check is read-only: it reserves and wakes nothing, and unlike admission it adds no further attempt reserve, so an attempt admitted under budget is not refused for its own reservation. A refusal for a token, a route or money is 401/403 with plain words that avoid the quota vocabulary, so a runner never mistakes it for a provider quota refusal and no route gets a wrong cooldown.
6. **No bodies, ever.** A request or a response is never stored or put in an event. Each call leaves one row: attempt, route, model, HTTP status, outcome (served, quota, failed, cancelled, refused), token counts read from the answer's `usage` (a stream is asked to report it), the cost priced with the route's prices, byte counts and duration. A request is bounded at 4 MiB, a relayed answer at 64 MiB and a call at ten minutes; the call is cancelled when the runner goes away.
7. **Spend is recorded once.** The attempt's spend stays what the runner reports at completion, priced with the route's prices, as ADR 0051 says; the gateway's rows are its measurement of the same calls, used for the in-flight money stop and for audit, and are not a second ledger.

## Consequences
- A runner on a gateway route needs no model key at all; the Governor host needs one `BRAIN_MODEL_KEY_*` per such route. The Governor must be reachable by the runner (it already is) and carries the model traffic of those routes.
- The runner's reported usage is still what settles spend, so a runner that under-reports is not corrected by the gateway's measurement; reconciling the two is left out.
- The advisory judge already runs on the Governor and is unchanged.
