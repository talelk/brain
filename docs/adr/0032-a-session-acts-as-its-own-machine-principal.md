# 32. A session acts as its own machine principal, recorded as acting for the mission owner

Status: accepted, 2026-11-15.

Machine actions were recorded under the mission owner's name: auto-start and coordinator wakes ran as the owner, and an agent session had no identity of its own to act with.

## Decision
1. **Principal.** Each team member of a mission has one machine principal (kind `agent`, id `agent:<mission>:<member>`; `agent:<mission>` for work no member is named for), created when first needed. It is bound to one workspace and mission and recorded as acting for the mission owner, who is looked up again each time, so an owner transfer moves it.
2. **Credential.** Each running attempt of an agent step gets a short-lived credential for that principal (`JobProtocol.sessionCredential`, runner-authenticated). It is checked against the attempt on every use: valid only while the attempt is running under the fence it was minted for, its lease and runner epoch current. Attempt end and lease loss also stamp it revoked; asking again replaces it. Principal per member, credential per attempt, so a replayed dispatch keeps its actor.
3. **Scope.** Deny by default, in two layers. A principal holds the `agent-session` role of the authorization matrix (read, `mission:write`) in its one workspace, intersected with what the owner may do there now; it has no membership of its own and never shows among a workspace's people. The command funnel admits only commands that name its own mission, directly or through a work item, plan version or run. On top of that, a session credential runs only the **session command allowlist**: the commands behind the governed Brain tools (`plan.propose`, `mission.message.send`, `handoff.submit`, `workItem.comment`; ADR 0042), whatever else the role's scope would admit. Work-item transitions, completion proposals, decisions, verdicts, closure, policy, brief, budget, confirmations and administration are refused (#159). Every command of the registry is classified admitted or refused in `packages/contracts/src/session-commands.ts`; a test enumerates the registry and fails on an unclassified command, so a new command is decided for sessions in the change that adds it. The Governor's own dispatches for a member (service credential) are not sessions.
4. **Attribution (every event, #148).** Every event records its actor in the event row itself: principal id and kind, the attempt it acted through, and `actingFor` when a machine principal acts for a person. The actor is not passed to `store.emit`; it is taken from the actor scope the work runs in (`actingAs`, an `AsyncLocalStorage`), which the command funnel sets from the caller of each command and which every other entry point sets by name: a session is its own principal acting for the owner through its attempt; a runner protocol call is the runner (with the attempt); the Governor's own service dispatch is `system:governor` acting for the person the work belongs to; every timer, pass and startup task is a named system principal (`system:watchdog`, `system:scheduler`, `system:projector`, `system:webhook:<endpointId>`). A scope replaces any enclosing one, so work a command starts does not inherit its person. No event has a null actor and none is attributed to the mission owner unless the owner did it. In a test run an event written outside any scope throws, so a new emit site cannot ship unattributed. The audit trail, the Logs explorer and the execution stream read the recorded actor and say it in a plain sentence ("By an agent working for Ana, through its session"); the separate `session.acted` event is gone, because the actor on each event says the same. Auto-start dispatches and coordinator runs use the assigned member's principal, not the owner.

## Consequences
- The owner no longer shares an actor with the agents that act for them: the requester of an effect on auto-started work is the agent, not the owner (ADR 0024 still needs a person's approval per effect).
- Attempts outside any mission have no agent principal: their events are the runner's. Schedule starts and the Governor's own mission completion are `system:*` principals acting for the person the work belongs to, not that person. The runner asks for the credential only to make a Brain tool call (ADR 0042).
