# 42. A Brain tool is one command run as the session principal

Status: accepted, 2026-11-15. Builds on ADR 0021 and 0024 (agents reach Brain only through operator-declared, release-pinned tools) and ADR 0032 (a session acts as its own machine principal).

An agent could not yet do anything inside Brain: no way to propose a change to its mission's plan, tell a teammate something, hand off its work or leave a note. Nothing in the runner used the session credential ADR 0032 made.

## Decision
1. **Four tools, one command each.** `mission.propose-plan` (`plan.propose`, origin agent), `mission.message-member` (`mission.message.send`), `mission.submit-handoff` (`handoff.submit`) and `mission.comment` (`workItem.comment`) are ordinary Tool documents of the release, allowlisted per agent like any tool (the starter's task worker lists them). The runner holds the table from tool to command type; the model names neither a command type nor an id it cannot know: the mission, the member and the task come from the Governor with the credential.
2. **The call runs as the principal.** On the first Brain call of an attempt the runner asks the Governor for the attempt's credential (`POST /runner/v1/attempts/:id/session-credential`, runner-authenticated; `JobProtocol.sessionCredential`) and makes the command at the public `/v1/commands` endpoint with it as bearer. The authorization matrix and the principal's own-mission scope decide (ADR 0032); the tool decides nothing. The credential lives in the runner's memory for the attempt, is asked for again before it expires, and is in no tool input, brokered data, event or artifact. The command id derives from the attempt and the proposal, so a retry is the same command. A refusal is a failed tool call with the Governor's plain reason and an instruction not to retry; a direct tool step or tool test, which has no principal, is refused.
3. **Class `read`, and why.** The effect class of ADR 0024 names effects outside Brain, each held at an approval. A Brain tool changes only Brain, as the person's delegate, within what that person may do; it has no outside effect to approve, so it is declared `read` and the supervisor sends it to the Brain broker, never to the effect gate. The Tool document's description says it changes Brain.
4. **Plan proposals.** A proposal inside the mission's autonomy policy is confirmed as it is proposed; one outside it, or before the mission has a confirmed plan, stays a plan proposal for a person (existing rule, unchanged). The tool reads the proposal back and tells the model which happened. Started work, intent, constraints and budget are not reachable: a plan version that changes started work is refused for every author.
5. **No tool decides.** No Brain tool maps to a verdict, a close, an approval, a confirmation, the autonomy policy, the brief or the budget, and the session role does not hold those commands either; a test drives the credential at each.
6. **Mission messages widen to team-member senders.** A session names another team member of its mission (never the mission itself, so it cannot wake the coordinator in a loop; never itself), cannot interrupt, and has at most five of its messages undelivered. The message lists its sender as the member's role, reaches the recipient labelled "From team member x" as a claim, and authorizes nothing.
7. **A session's own comment stays only in the thread.** A message is the explicit way to reach a member; a comment that also became one would give the same text two paths and let a session message itself (or fall back to waking the coordinator) just by commenting on its own task. Decided against; #100's rule stands.

## Limits
- "Read" for a tool that writes is a convention a reader must be told; the registry shows the description, not a separate class.
- A session may submit a handoff or comment on any work item of its own mission through the command; the tools default to the task it serves and take only a work item named in a comment.
- Messages between members are bounded by the pending limit and the budget of the sessions that read them, not by a rate limit.
