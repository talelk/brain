## Changes
- Design language in `apps/web/src/index.css` (polish layer): one focus ring (2 px accent, 2 px offset) for every interactive element in both themes; press feedback on buttons; page content eases in once; reduced motion stays honoured by the existing global rule; themed `body` canvas so pages outside the shell (shared result, sign-in, wallboard) follow dark mode.
- Plan decision bar (`PlanCanvas`): Confirm, Edit steps and Reject now live in one sticky bar. Desktop: top of the plan area, follows the reader. Phone: bottom, safe-area aware, Confirm full width over Edit and Reject. One primary action.
- Friendly names: `app.personName(id)` gives "you", the member's display name or "a teammate". Used on Today, Approvals list, detail, history and review dialog. Live titles fall back to "<agent> session", rail runs to "Run"; the mission Logs tab names each run by its task.
- Microcopy: user-visible "Governor" became "Brain"; Schedules and Today descriptions shortened; Schedules empty state tells you what to do next; session filter placeholder no longer says "id".
- Touch targets at 639 px and below: 44 px minimum for buttons, selects, tabs, toggle items, header buttons, breadcrumb links, text inputs.
- Schedules list is full width.
- Tests: `Today` heading in four specs, `Brain could not complete this read` in the a11y spec.

## Track E3 (2026-11-11)
- Suite: with only the vitals change, the full browser suite at 1440-light, 390-dark and 768-light was 207 passed (32 min, nothing flaky). The "264 KB" Today budget failure was a measurement artefact: the service worker takes control mid-load (`skipWaiting` + `clients.claim`) and re-serves later chunks through `fetch()`, which reports their decoded size as `encodedBodySize` (Select 27 KB instead of 7.7 KB gzip, TodayPage 19 KB instead of 6 KB). Real wire size is 207 KB for Today and 176 KB for the setup screen against 250 KB, so no chunk splitting was needed. `vitals.spec.ts` now blocks the service worker (`test.use({ serviceWorkers: "block" })`); the budget is unchanged. The 768 INP failure did not reproduce alone or in the full run; the 432 ms INP seen once in a loaded run was the same worker re-fetch plus a busy machine.
- Capture helper: `scripts/capture-screens.ts` (`pnpm exec tsx scripts/capture-screens.ts [outDir] --widths --schemes --only`) seeds the demo workspace, captures about 38 screens full height at every width and scheme and prints any page that scrolls sideways.
- Today: the box leads on every viewport (compact: one row of chips, "More options" collapsed); Needs you sits under it, capped at three with "N more"; setup checklist follows the box even while blocked; "Results ready" is one summary row that expands to the newest eight, no "Waiting since" wording, "Mark all seen" (remembered per browser). Result rows elsewhere (bell, Missions) say "Finished ...", and drop the "Result ready:" and "is verified and done" wrapping.
- "Verify the install" (backlog 37): readiness treats any work item that reached done (a table check guarantees accepted evidence) after the last model test as proof, same as an `agent-smoke` run. The release fix from Today now carries `from=today` and shows "Back to Today when you are done".
- Mission Live: workflow-run sessions were created without a work item, so the mission read model could not attach them and said "Nobody is working". `recordAttemptSession` now stores the work item of the run's execution link. With no session yet the tab says "Starting: waiting for a runner" or "Waiting for the independent check". "While you were away" counts use plain words. Test: `tests/integration/workflow-session-link.test.ts`.
- Polish: loading skeletons shimmer (reduced motion stops it); Library shelves are one compact line each on phones; the Logs chart no longer reserves a blank band under the axis; fingerprints on Today approvals and Knowledge review use the copy control with a plain label; tool versions, ticket and incident dates, Health activity (event words, "By Brain", no cursor numbers) lost raw ids and ISO strings.
- Baselines: added `*-1440-dark`, `*-768-dark`, `*-390-light` for all twelve screens; regenerated `logs-1440-light`, `logs-768-light`, `logs-390-dark` (tighter chart) and `missions-390-dark` (result row wording).
- Leftovers: Library tab strip wraps to two indented rows on 390; the approvals and runners summary bars look heavy when they hold a single segment; time-axis labels in the Logs chart switched to 12-hour; Today unblocked state (runners online) was checked in tests, not by eye on a live instance.
