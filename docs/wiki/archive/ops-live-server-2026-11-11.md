## Optional notification webhook (2026-11-11, ADR 0011)
Set `BRAIN_NOTIFY_WEBHOOK_URL` (https, or http on localhost) and optionally `BRAIN_NOTIFY_WEBHOOK_SECRET` in the Governor's environment to offer people the webhook channel. The body is a link only (`{type, kind, text, link, count?}`), signed with `x-brain-signature: sha256=<hmac>` when a secret is set. Unset means a safe no-op and the preference shows as unavailable. Share links use `BRAIN_BASE_URL` for their address.

## Runner capacity and readiness (2026-11-11, track T)
- Readiness (`/v1/doctor`) judges a runner on capability, not on free slots: "No online capable runner" only when no enabled, online, healthy runner with the right group/engine exists (offline, disabled, draining and incapable runners count as missing). A runner with every slot in use is ready, with `busy: {slotsInUse, slotsTotal}` on the check and the detail "busy: N of M slots in use". Today never blocks the box for it; it shows "Brain is working on N things; yours queues and starts next."
- The runner process now runs one claim loop per slot. Environment (read by `apps/runner/src/supervisor.ts`): `BRAIN_RUNNER_SLOTS` (default 1), `BRAIN_RUNNER_CPU_MILLICORES` (default 4000), `BRAIN_RUNNER_MEMORY_MB` (default 8192). A job reserves its own CPU/memory/slot from the step's `resources` (starter steps: 500 mCPU, 256-512 MB, 1 slot) and the Governor keeps 500 mCPU / 1024 MB aside, so 3 agent sessions fit in 4000 mCPU / 8192 MB.
- Deploy: `scripts/deploy-demo.sh` uses `BRAIN_DEPLOY_AGENT_SLOTS` (default 3), `BRAIN_DEPLOY_EVALUATOR_SLOTS` (default 2), `BRAIN_DEPLOY_RUNNER_CPU_MILLICORES`, `BRAIN_DEPLOY_RUNNER_MEMORY_MB`. First deploy writes them into `runner-*.env`; every later deploy upserts the same lines (idempotent `set_runner_env`) before restarting the runner units, so the unit files themselves do not change. Local `scripts/up.sh` / `enroll-local-runners.ts` default to 3 agent and 2 evaluator slots (`BRAIN_AGENT_SLOTS`, `BRAIN_EVALUATOR_SLOTS`).
- Session refresh (2026-11-11, track AE, tests/chaos/runner-concurrency.test.ts): a runner re-hellos about every 10 min (and on 401) with the boot nonce of its first hello, which keeps the epoch and only replaces the token; every client follows the current token, and a timer refreshes even when all slots are busy. Running attempts are never dropped and no worker waits for them. A restarted runner process has a new nonce, a new epoch, and its old attempts are fenced until their leases lapse. Runner code must be redeployed (restart runners) for this.
- Optional email for notifications: `BRAIN_NOTIFY_SMTP_URL` (smtp(s)://user:pass@host:port) and `BRAIN_NOTIFY_FROM` on the Governor; unset means off. New table `email_deliveries` and column `notification_preferences.email` (DEFAULT 0); see ADR 0011 amendment.
