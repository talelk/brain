## Flaky browser specs

Reproduced with 20 to 24 busy threads on a 14-core machine:

- vitals: the old budget took the longest of every event entry, which includes pointer moves (not interactions) and the wait before the main thread could look at an event. Handlers took 0 to 45 ms; the 100 to 150 ms were the next frame after the search dialog opened and the wait before it. Now only real interactions count (interaction id) and the budget is handler plus paint (200 ms); the wait is reported, not charged to the app.
- exec-console: asserted at the first poll that Steer was hidden, but a session whose task belongs to a mission offers steering once the mission link has loaded (recorded in the brief). It passed on a quiet machine only because the link had not loaded yet. Now it waits for the control to settle and checks what it offers; the recorded control is polled.
- mission-board idle re-render: counted the first reads landing late as re-rendering. Idle now starts when the document has been quiet for 1.5 s.
- first-launch (and any expectation at the default 5 s): `expect.timeout` is 15 s for a busy shared machine.
