# Deployment reference status

These are nondeployable topology references until T48 provides and pins actual images, boot/health entrypoints, TLS, initialized volume ownership and secrets. They intentionally fail interpolation when required settings are absent. No image tagged latest is supplied.

Every variable in these files is one the apps read, and `tests/contracts/deploy-env.test.ts` fails when a file sets one that no app does. The Governor reads `BRAIN_BASE_URL` (the public origin), `BRAIN_DATA_DIR`, `BRAIN_WEB_DIST_DIR` (the static web bundle in its image), `PORT` and `BRAIN_BIND_HOST`; it derives its signing keys from files it creates in the data volume, so no secret is passed. The runner reads `BRAIN_GOVERNOR_URL`, `BRAIN_RUNNER_ID`, `BRAIN_RUNNER_STATE_DIR`, `BRAIN_RUNNER_SLOTS` (concurrent sessions, default 1) and, on its first boot only, `BRAIN_RUNNER_ENROLL_TOKEN`: it enrolls, then keeps its credential in `<state dir>/credential.txt` on the `runner_state` volume. A release is staged through the CLI, not mounted. The web bundle's reviewed foundation manifest digest is checked at config activation (`BrainConfig.spec.ui.foundationManifestDigest`). YAML never triggers package installation, downloads or a separate UI runtime service. Preserve auth/API/MCP/runner routes when implementing SPA fallback; a missing asset returns 404 rather than HTML.

The validated reference build profile is `examples/v1/config/web-build.json`; Vite/CSS consumer examples are under `examples/v1/web/`. Source package versions there remain candidates until G01/T33 installation and production build gates pass.

The supervisor's resource limits exclude separately launched job containers. The trusted launcher enforces independent cgroup/egress/mount profiles and authenticates the supervisor socket. An agent container never receives the launcher socket. Sandbox egress is enforced by the `egress-proxy` service in `compose.runner.yaml` (ADR 0037): sandboxes join the internal `brain-internal` network, the proxy is its only way out, and each sandbox may reach only its workspace's hosts (set under Administration, How work runs). Set `BRAIN_LAUNCHER_EGRESS_GRANTS_DIR` on the launcher to the directory the proxy mounts as `BRAIN_EGRESS_GRANTS_DIR`; without it the launcher gives no sandbox a network. Engines run in per-attempt sandboxes (ADR 0067), and the runner states `ephemeral-container` for Pi, Claude and ACP engines only while it can start them. The launcher needs `BRAIN_LAUNCHER_ENGINE_STATE_ROOT` (a host directory; the runner mounts the same one as `BRAIN_RUNNER_ENGINE_STATE_DIR`), the egress grants directory above, the image `brain-sandbox-engine` (`deploy/engine-sandbox.Dockerfile`), and optionally `BRAIN_LAUNCHER_ENGINE_USER` (`uid:gid`, default the launcher's; it must be able to write the runner's attempt directories) and `BRAIN_LAUNCHER_ENGINE_IDLE_MS`. The model host joins each sandbox's allowed hosts from its route or the runner's model setting; an ACP agent's hosts go in `BRAIN_ENGINE_MODEL_HOSTS` on the runner. Without these the attempt fails with `engine sandbox create failed`; it never runs in the runner.

TencentDB deployment must be generated from the pinned upstream service manifests after G04, then adapted to private bindings/volumes/resource budgets. No invented MemoryCore image tag, secret-file option or completeness guarantee is included. Optional Victoria/ntfy services likewise need reviewed versions/config before enabling.

Render both references with supplied disposable paths/values in T48 using `rtk docker compose -f <file> config`, then run health, permissions, restart and rootless isolation scenarios. The current pack checks YAML shape and forbidden mounts only; it does not certify a running deployment.
